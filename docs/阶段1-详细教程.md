## 2. 第 0 步：先搞懂我们要做什么

### 2.1 一句话目标

做一套接口，让前端能**查商家**：分页列表、按条件筛选、看详情、后台能增删改。

### 2.2 请求是怎么走完全程的

这是**最重要的一张图**，理解它，后面所有代码你都能自己推出来：

```
Postman / 浏览器
      │  GET /shop/page?type=美食&page=1
      ▼
┌─────────────────┐
│  ShopController │  ① 接参数、做参数校验、返回统一格式
└────────┬────────┘
         │ 调用
         ▼
┌─────────────────┐
│   ShopService   │  ② 业务逻辑（判断、组装、缓存——阶段2加）
└────────┬────────┘
         │ 调用
         ▼
┌─────────────────┐
│   ShopMapper    │  ③ 只负责和数据库说话
└────────┬────────┘
         │ SQL
         ▼
      MySQL (shop 表)
```

### 2.3 每一层到底该写什么（分层铁律）

| 层 | 类名后缀 | 只做这些事 | **绝对不能**做这些事 |
|---|---|---|---|
| Controller | `XxxController` | 接参数、参数校验、调 Service、包装返回 | ❌ 写 SQL ❌ 写业务判断 ❌ 直接操作 Redis |
| Service | `XxxService` / `XxxServiceImpl` | 业务逻辑、事务、缓存、调用多个 Mapper | ❌ 直接暴露给前端 ❌ 处理 HTTP 细节 |
| Mapper | `XxxMapper` | 数据库增删改查 | ❌ 写业务逻辑 |
| Entity | `Xxx` | 和数据库表一一对应的字段 | ❌ 写业务方法 |

> **为什么要分层？** 因为当项目变大（比如后面要加缓存、加秒杀），你只需要改 Service 一层，Controller 一个字都不用动。混在一起写，后期就是灾难。

### 2.4 我们要产出的文件清单

```
common/Result.java                    统一返回格式
common/BusinessException.java         业务异常
common/GlobalExceptionHandler.java    统一异常出口
config/MybatisPlusConfig.java         分页插件
config/MyMetaObjectHandler.java       自动填充时间
config/RedisConfig.java               Redis 序列化配置
entity/Shop.java                      商家实体
mapper/ShopMapper.java                数据库操作
dto/ShopQueryDTO.java                 查询条件入参
service/ShopService.java              业务接口
service/impl/ShopServiceImpl.java     业务实现
controller/ShopController.java        接口入口
```

## 3. 第 1 步：确认 pom.xml 依赖

打开 `pom.xml`，确认 `<dependencies>` 里有这些。**这些不需要你手敲**，检查一下在不在就行：

```xml
<!-- Web：提供 @RestController、内嵌 Tomcat -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
</dependency>

<!-- 参数校验：@NotBlank、@Valid -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-validation</artifactId>
</dependency>

<!-- Redis 客户端 -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-redis</artifactId>
</dependency>

<!-- 数据库操作框架 -->
<dependency>
    <groupId>com.baomidou</groupId>
    <artifactId>mybatis-plus-spring-boot3-starter</artifactId>
    <version>3.5.5</version>
</dependency>

<!-- MySQL 驱动 -->
<dependency>
    <groupId>com.mysql</groupId>
    <artifactId>mysql-connector-j</artifactId>
    <scope>runtime</scope>
</dependency>

<!-- Lombok：用 @Data 自动生成 getter/setter -->
<dependency>
    <groupId>org.projectlombok</groupId>
    <artifactId>lombok</artifactId>
    <optional>true</optional>
</dependency>
```

**几个概念解释**：

- `<scope>runtime</scope>`：编译时用不到，运行时才需要。MySQL 驱动就属于这种——你的代码里从来不会 `import` 它，但启动时必须要有。
- `<optional>true</optional>`：这个依赖不会传递给引用你项目的人。Lombok 只是编译期帮你生成代码，编译完就没用了。
- **版本为什么可以不写？** 因为你的 parent 是 `spring-boot-starter-parent`，它内部有一份"依赖版本清单"（BOM）。只要是 Spring 官方管着的依赖，版本它自动帮你定，你写反而容易冲突。MyBatis-Plus 不是 Spring 官方的，所以必须自己写版本号。

> ⚠️ 检查一下 **Lombok 插件**装了没：`File → Settings → Plugins`，搜 `Lombok`。还要在 `Settings → Build, Execution, Deployment → Compiler → Annotation Processors` 里勾上 `Enable annotation processing`。没装的话 `@Data` 生成的 getter/setter 会全部报红。

## 4. 第 2 步：建库建表

### 4.1 执行 SQL

打开 `sql/init.sql`，在 IDEA 的数据库工具（右侧 `Database` 面板）或 Navicat / 命令行里**整个执行一遍**。

如果你还没在 IDEA 里连数据库：右侧 `Database` → `+` → `Data Source` → `MySQL` → 填 `localhost:3306` / 用户 `root` / 你的密码 → `Test Connection` 通过后 `OK`。

### 4.2 表结构讲解

```sql
CREATE DATABASE IF NOT EXISTS `zhilan`
    DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;

CREATE TABLE `shop` (
    `id`             BIGINT        NOT NULL AUTO_INCREMENT COMMENT '主键',
    `name`           VARCHAR(64)   NOT NULL COMMENT '商家名称',
    `type`           VARCHAR(32)   NOT NULL COMMENT '类型',
    `city`           VARCHAR(32)   DEFAULT NULL COMMENT '城市',
    `address`        VARCHAR(255)  DEFAULT NULL COMMENT '详细地址',
    `phone`          VARCHAR(20)   DEFAULT NULL COMMENT '联系电话',
    `business_hours` VARCHAR(64)   DEFAULT NULL COMMENT '营业时间',
    `avg_price`      DECIMAL(10,2) DEFAULT NULL COMMENT '人均价格',
    `score`          DECIMAL(2,1)  DEFAULT 5.0  COMMENT '评分',
    `sales`          INT           DEFAULT 0    COMMENT '销量',
    `comments`       INT           DEFAULT 0    COMMENT '评论数',
    `images`         VARCHAR(1024) DEFAULT NULL COMMENT '图片URL，逗号分隔',
    `description`    TEXT          COMMENT '简介',
    `status`         TINYINT       DEFAULT 1    COMMENT '状态 1营业 0停业',
    `deleted`        TINYINT       DEFAULT 0    COMMENT '逻辑删除',
    `create_time`    DATETIME      DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    `update_time`    DATETIME      DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    PRIMARY KEY (`id`),
    KEY `idx_type` (`type`),
    KEY `idx_city` (`city`)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COMMENT = '商家表';
```

**每个设计点都要理解**（面试也爱问）：

| 设计 | 为什么 |
|---|---|
| `utf8mb4` 而不是 `utf8` | MySQL 的 `utf8` 是**假的**，存不了 emoji 😂。`utf8mb4` 才是真 UTF-8。 |
| `DECIMAL(10,2)` 存价格 | **钱绝对不能用 `float`/`double`**，浮点数有精度误差（0.1+0.2≠0.3）。金额一律用 DECIMAL。 |
| `DECIMAL(2,1)` 存评分 | 2 位总长、1 位小数，即 `4.8`。 |
| `deleted` 逻辑删除字段 | 删除时**不真删**，只把 `deleted` 改成 1。这样数据可追溯、可恢复，也不会因为外键关联导致报错。 |
| `create_time` / `update_time` | 加 `ON UPDATE CURRENT_TIMESTAMP` 后，MySQL 会在每次更新时自动改 `update_time`。 |
| `KEY idx_type` / `idx_city` | 给经常用来筛选的字段建**索引**，查询快。不建的话每查一次都要全表扫描。 |

### 4.3 验证

在数据库工具里执行：

应该看到 5 条示例数据（老王火锅、星聚咖啡……）。**看不到就是没执行成功，先解决这个再往下走。**

```yaml
  data:
    redis:
      host: localhost
      port: 6379
      password:                      # 没设密码就留空
      database: 0

  jackson:
    date-format: yyyy-MM-dd HH:mm:ss   # 返回给前端的时间格式
    time-zone: Asia/Shanghai

mybatis-plus:
  configuration:
    map-underscore-to-camel-case: true  # 数据库 business_hours → 实体 businessHours
    log-impl: org.apache.ibatis.logging.slf4j.Slf4jImpl  # 打印执行的 SQL
  global-config:
    banner: false
    db-config:
      id-type: auto                     # 主键自增
      logic-delete-field: deleted       # 逻辑删除字段
      logic-delete-value: 1             # 已删除
      logic-not-delete-value: 0         # 未删除

logging:
  level:
    com.zhilan.zhilanserver: debug      # 你自己的包打印 debug 日志
```

### 逐段讲解（重点看这段）

**① `driver-class-name`**：MySQL 8 的驱动类名是 `com.mysql.cj.jdbc.Driver`（带 `cj`）。
老教程里写的 `com.mysql.jdbc.Driver` 是 MySQL 5 的，在 8 上会警告甚至报错。

**② URL 里那几个参数，一个都不能少**（这是新手最常踩的坑）：

| 参数 | 作用 | 不写会怎样 |
|---|---|---|
| `serverTimezone=Asia/Shanghai` | 指定时区 | ❌ 报 `The server time zone value '?D1ú±ê×?ê±??' is unrecognized` |
| `useSSL=false` | 关掉 SSL | ⚠️ 启动时一堆红色警告 |
| `allowPublicKeyRetrieval=true` | 允许获取公钥 | ❌ MySQL 8 默认加密方式下连接被拒 |
| `characterEncoding=utf8` | 字符编码 | ⚠️ 中文乱码 |

**③ `map-underscore-to-camel-case: true`**：这是**驼峰映射**。
数据库字段叫 `business_hours`（下划线风格），Java 字段叫 `businessHours`（驼峰风格）。开了这个开关，MyBatis 会自动帮你对应上；不写你就得在每个字段上加 `@TableField("business_hours")`，累死。

**④ `log-impl: ...Slf4jImpl`**：会在控制台打印 MyBatis 实际执行的 SQL。
**强烈建议开着**——出问题时你能直接看到 SQL 长什么样，是排查问题最有效的手段。

**⑤ `logic-delete-field: deleted`**：全局配置逻辑删除。
配了它之后，你调 `removeById()`，MyBatis-Plus 实际执行的是 `UPDATE shop SET deleted=1 WHERE id=?` 而不是 `DELETE`；查询时会自动帮你加上 `WHERE deleted=0`。**这就是为什么你查数据永远看不到已删除的。**

现在别急着启动（还没有任何 Controller，启动也会因为没配数据库报错）。写完后面的代码再一起启动。

## 6. 第 4 步：Result 统一返回

**文件**：`com/zhilan/zhilanserver/common/Result.java`

### 为什么需要它

如果每个接口返回的结构都不一样，前端要疯：

```json
// 接口A返回
{ "id": 1, "name": "老王火锅" }
// 接口B返回
"success"
// 接口C出错返回
{ "error": "商家不存在", "timestamp": 1234567 }
```

统一成 `{code, msg, data}` 之后，前端只要判断 `code === 200` 就行：

```json
{ "code": 200, "msg": "success", "data": { "id": 1, "name": "老王火锅" } }
```

### 代码

```java
package com.zhilan.zhilanserver.common;

import lombok.Data;

import java.io.Serializable;

/**
 * 统一返回结构
 */
@Data
public class Result<T> implements Serializable {

    /** 200 成功；400 参数错误；401 未登录；500 系统错误 */
    private int code;
    private String msg;
    private T data;

    public static <T> Result<T> ok() {
        return ok(null);
    }

    public static <T> Result<T> ok(T data) {
        Result<T> r = new Result<>();
        r.code = 200;
        r.msg = "success";
        r.data = data;
        return r;
    }

    public static <T> Result<T> fail(String msg) {
        return fail(500, msg);
    }

    public static <T> Result<T> fail(int code, String msg) {
        Result<T> r = new Result<>();
        r.code = code;
        r.msg = msg;
        return r;
    }
}
```

### 逐行讲解

**`@Data`**：Lombok 注解，编译时自动生成 `getCode()`、`setCode()`、`toString()`、`equals()` 等方法。源码里看不到，但编译后 class 文件里有。所以 IDE 里如果 getter 报红，就是 Lombok 插件/注解处理没配好。

**`<T>` 泛型**：`T` 是"待定的类型"。`Result<Shop>` 的 `data` 就是 `Shop`，`Result<Page<Shop>>` 的 `data` 就是 `Page<Shop>`。这样一个类能装任何数据，不用为每种类型写一个 Result。

**`implements Serializable`**：标记这个类可以被序列化。理论上不写也能返回 JSON，但**如果你将来要把对象存进 Redis（阶段 2 就会），就必须序列化**，所以养成习惯写上。

**`public static <T> Result<T> ok(T data)`**：
- `static`：静态工厂方法，可以直接 `Result.ok(...)` 调用，不用 `new`。
- 方法上**自己声明了 `<T>`**：这是"泛型方法"。它告诉编译器："调用这个方法时，T 由传进来的参数决定"。这样 `Result.ok(shop)` 返回的就是 `Result<Shop>`，不用强制转换。

**为什么用静态工厂方法而不是 `new Result<>()`？**
因为调用方更省事，而且语义清晰：`Result.ok(data)` 一眼就知道是成功。

> **思考题**：`ok()` 和 `ok(null)` 的区别？——没区别，`ok()` 就是偷懒写法。

## 7. 第 5 步：BusinessException 业务异常

**文件**：`com/zhilan/zhilanserver/common/BusinessException.java`

### 为什么需要它

当"商家不存在"时，你希望接口返回 `{code:404, msg:"商家不存在"}`，而不是一坨 Java 异常堆栈给用户看。

但直接 `throw new RuntimeException("商家不存在")` 不行——因为**所有 RuntimeException 长得都一样**，全局异常处理器没法区分"这是业务问题（该告诉用户）"还是"这是代码 bug（不该暴露）"。

所以我们要自定义一个异常类型当"标记"：

```java
package com.zhilan.zhilanserver.common;

import lombok.Getter;

/**
 * 业务异常：由全局异常处理器统一转成 Result 返回
 */
@Getter
public class BusinessException extends RuntimeException {

    private final int code;

    public BusinessException(String message) {
        this(500, message);
    }

    public BusinessException(int code, String message) {
        super(message);
        this.code = code;
    }
}
```

### 逐行讲解

**`extends RuntimeException`**：继承运行时异常。这样调用处**不需要**写 `try-catch` 或 `throws`（受检异常才必须处理），代码干净。

**`private final int code`**：额外带一个状态码，这样全局处理器能知道该返回 400 还是 404。`final` 表示创建后不能改。

**`this(500, message)`**：构造方法里调用另一个构造方法，默认错误码 500。

**`super(message)`**：把消息交给父类 `RuntimeException` 保存，之后 `getMessage()` 就能取到。

**`@Getter`**：Lombok 只生成 getter（不需要 setter，因为 `final`）。

### 用起来长这样

```java
if (shop == null) {
    throw new BusinessException(404, "商家不存在");
}
```

## 8. 第 6 步：GlobalExceptionHandler 全局异常处理

**文件**：`com/zhilan/zhilanserver/common/GlobalExceptionHandler.java`

### 为什么需要它

**想象没有它**：10 个接口，每个都要写 `try-catch`，重复且容易漏。漏了的地方出错就直接给前端返回 500 + 一堆堆栈，很难看。

**有了它**：所有异常自动汇聚到一个地方统一处理，业务代码里只管 `throw`，不用管怎么返回。

```java
package com.zhilan.zhilanserver.common;

import lombok.extern.slf4j.Slf4j;
import org.springframework.validation.BindException;
import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;

/**
 * 全局异常处理
 */
@Slf4j
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(BusinessException.class)
    public Result<Void> handleBusiness(BusinessException e) {
        log.warn("业务异常: code={}, msg={}", e.getCode(), e.getMessage());
        return Result.fail(e.getCode(), e.getMessage());
    }

    @ExceptionHandler({MethodArgumentNotValidException.class, BindException.class})
    public Result<Void> handleValid(BindException e) {
        String msg = e.getBindingResult().getFieldErrors().stream()
                .map(f -> f.getField() + ": " + f.getDefaultMessage())
                .findFirst()
                .orElse("参数校验失败");
        return Result.fail(400, msg);
    }

    @ExceptionHandler(IllegalArgumentException.class)
    public Result<Void> handleIllegalArgument(IllegalArgumentException e) {
        return Result.fail(400, e.getMessage());
    }

    @ExceptionHandler(Exception.class)
    public Result<Void> handleException(Exception e) {
        log.error("系统异常", e);
        return Result.fail(500, "系统繁忙，请稍后再试");
    }
}
```

### 逐行讲解

**`@RestControllerAdvice`**：核心注解。它 = `@ControllerAdvice` + `@ResponseBody`。
意思是"**给所有 Controller 加一层环绕的通知**"，配合 `@ExceptionHandler` 就能拦截整个应用抛出的异常。

**`@ExceptionHandler(BusinessException.class)`**：声明"当抛出 BusinessException 时，用我这个方法来处理"。
方法返回值会被自动转成 JSON 返回给前端。

**异常处理的匹配规则（重要）**：Spring 会找**最匹配**的那个处理器。
所以 `BusinessException` 走第一个，参数校验异常走第二个，其余所有异常落到最后的 `Exception` 兜底。

**`Result<Void>`**：`Void` 表示"没有数据要返回"，只有 code 和 msg。

**`log.warn` vs `log.error`**：
- 业务异常是**预期内**的（用户输入错了、商家不存在），用 `warn`，日志级别低。
- 系统异常是**意外**的（空指针、数据库挂了），用 `error` 并打印完整堆栈。
- ⚠️ **这是个好习惯**：如果把业务异常也打成 error，你的日志会被"商家不存在"刷屏，真正的 bug 反而被淹没。

**`e.getBindingResult().getFieldErrors()`**：`@Valid` 校验失败后，所有失败信息都在这里。`.stream().map(...).findFirst()` 是取出第一条，拼成 `name: 商家名称不能为空` 这种好读的格式。

**最后那个 `Exception` 兜底为什么重要？**
注意它返回的是 `"系统繁忙，请稍后再试"`——**故意不把真实异常信息暴露给前端**。因为真实信息可能包含 SQL、表名、文件路径，这些是安全隐患。真实原因只记在服务端日志里。

## 9. 第 7 步：MybatisPlusConfig 分页插件

**文件**：`com/zhilan/zhilanserver/config/MybatisPlusConfig.java`

### 为什么需要它

**这是新手必踩的坑**：MyBatis-Plus 的分页**不是自动生效的**，必须手动注册一个拦截器。

不注册的后果很隐蔽：你调 `page()`，它**不报错**，但返回的是**全部数据**——你以为分页了，其实没有。数据量一大直接把内存打爆。

```java
package com.zhilan.zhilanserver.config;

import com.baomidou.mybatisplus.annotation.DbType;
import com.baomidou.mybatisplus.extension.plugins.MybatisPlusInterceptor;
import com.baomidou.mybatisplus.extension.plugins.inner.PaginationInnerInterceptor;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

/**
 * MyBatis-Plus 配置：分页插件
 */
@Configuration
public class MybatisPlusConfig {

    @Bean
    public MybatisPlusInterceptor mybatisPlusInterceptor() {
        MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();
        interceptor.addInnerInterceptor(new PaginationInnerInterceptor(DbType.MYSQL));
        return interceptor;
    }
}
```

### 逐行讲解

**`@Configuration`**：标记这是"配置类"。Spring 启动时会扫描它，把它里面 `@Bean` 标注的方法都执行一遍，把返回值放进 Spring 容器。

**`@Bean`**：告诉 Spring："这个方法的返回值交给你管理"。
方法名 `mybatisPlusInterceptor` 默认就是 Bean 的名字。

**什么是"拦截器"？**
MyBatis-Plus 通过拦截 SQL 执行过程来实现功能。分页拦截器的原理是：
1. 你调用 `page(new Page(1, 10), wrapper)`
2. 拦截器发现这是个分页查询
3. 它自动改写 SQL：`SELECT * FROM shop` → `SELECT * FROM shop LIMIT 0,10`
4. 同时再发一条 `SELECT COUNT(*)` 统计总数

**`DbType.MYSQL`**：告诉插件用哪种数据库的方言。因为不同数据库分页语法不同（MySQL 用 `LIMIT`，Oracle 用 `ROWNUM`）。写错了分页会失效。

## 10. 第 8 步：MyMetaObjectHandler 自动填充时间

**文件**：`com/zhilan/zhilanserver/config/MyMetaObjectHandler.java`

### 为什么需要它

`create_time` 和 `update_time` 每次都要手动 `setCreateTime(LocalDateTime.now())` 太啰嗦，而且容易忘。MyBatis-Plus 提供了"自动填充"机制。

```java
package com.zhilan.zhilanserver.config;

import com.baomidou.mybatisplus.core.handlers.MetaObjectHandler;
import org.apache.ibatis.reflection.MetaObject;
import org.springframework.stereotype.Component;

import java.time.LocalDateTime;

/**
 * 自动填充 createTime / updateTime
 */
@Component
public class MyMetaObjectHandler implements MetaObjectHandler {

    @Override
    public void insertFill(MetaObject metaObject) {
        this.strictInsertFill(metaObject, "createTime", LocalDateTime.class, LocalDateTime.now());
        this.strictInsertFill(metaObject, "updateTime", LocalDateTime.class, LocalDateTime.now());
    }

    @Override
    public void updateFill(MetaObject metaObject) {
        this.strictUpdateFill(metaObject, "updateTime", LocalDateTime.class, LocalDateTime.now());
    }
}
```

### 逐行讲解

**`@Component`**：把这个类交给 Spring 管理（它是一个 Bean，不是配置类，所以用 `@Component` 而不是 `@Configuration` + `@Bean`）。

**`implements MetaObjectHandler`**：实现 MyBatis-Plus 定义的接口。

**`insertFill`**：执行 `INSERT` 时被调用。新增数据时，`createTime` 和 `updateTime` 都填当前时间。
**`updateFill`**：执行 `UPDATE` 时被调用。只有 `updateTime` 变，`createTime` 不动。

**`strictInsertFill(metaObject, "createTime", LocalDateTime.class, 值)`** 的四个参数：
1. `metaObject`：MyBatis 包装的实体对象（不用管，框架传进来的）
2. `"createTime"`：**要填充的 Java 属性名**（不是数据库字段名！）
3. `LocalDateTime.class`：类型
4. 值

**`strict` 前缀的含义**：只在字段值为 `null` 时才填充。
如果你手动 `setCreateTime(...)` 了，它就不会覆盖你的值。这很合理。

> **注意**：光有这个类还不够！实体类上必须加 `@TableField(fill = ...)` 注解，两个配合才生效（第 10 步会讲）。

## 11. 第 9 步：RedisConfig

**文件**：`com/zhilan/zhilanserver/config/RedisConfig.java`

### 为什么需要它（这是个"坑点"）

Spring Boot 自动给你一个 `RedisTemplate`，但它**默认用 JDK 序列化**，存进 Redis 的数据长这样：

```
\xac\xed\x00\x05sr\x00\x15com.zhilan...
```

一堆乱码，用 `redis-cli` 根本看不懂，而且换语言/换类都会反序列化失败。

我们把它改成 **key 用字符串、value 用 JSON**，这样 `redis-cli` 里能看到人话：

```java
package com.zhilan.zhilanserver.config;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.data.redis.connection.RedisConnectionFactory;
import org.springframework.data.redis.core.RedisTemplate;
import org.springframework.data.redis.serializer.GenericJackson2JsonRedisSerializer;
import org.springframework.data.redis.serializer.StringRedisSerializer;

/**
 * Redis 配置：key 用 String，value 用 JSON
 */
@Configuration
public class RedisConfig {

    @Bean
    public RedisTemplate<String, Object> redisTemplate(RedisConnectionFactory factory) {
        RedisTemplate<String, Object> template = new RedisTemplate<>();
        template.setConnectionFactory(factory);

        StringRedisSerializer keySerializer = new StringRedisSerializer();
        GenericJackson2JsonRedisSerializer valueSerializer = new GenericJackson2JsonRedisSerializer();

        template.setKeySerializer(keySerializer);
        template.setHashKeySerializer(keySerializer);
        template.setValueSerializer(valueSerializer);
        template.setHashValueSerializer(valueSerializer);
        template.afterPropertiesSet();
        return template;
    }
}
```

### 逐行讲解

**`RedisConnectionFactory factory` 参数**：Spring 会自动注入（因为 `application.yaml` 里配了 Redis）。这就是**依赖注入**——你不用自己 `new`，Spring 把现成的给你。

**`StringRedisSerializer`**：把字符串按 UTF-8 转成字节。key 用它，`redis-cli` 里就能看到 `shop:1` 这样的可读 key。

**`GenericJackson2JsonRedisSerializer`**：把对象转成 JSON 存。
它有个特点：**会在 JSON 里额外存一个 `@class` 字段**记录原始类型，比如：

```json
{"@class":"com.zhilan.zhilanserver.entity.Shop","id":1,"name":"老王火锅"}
```

这样 `get` 的时候它能自动还原成 `Shop` 对象，不用你自己转。**代价是存了类名，占点空间，而且类改包名后旧数据会反序列化失败**——知道这个权衡就行。

**为什么要设 4 个序列化器？**
Redis 的数据分两类：普通 key-value，和 hash 结构。每类都有 key 和 value 两部分，所以一共 4 个。

**`template.afterPropertiesSet()`**：让 template 完成内部初始化。**这一行不能漏**，漏了可能报参数校验失败。

> **补充知识**：如果只是存简单字符串（比如验证码），直接用 Spring 自带的 `StringRedisTemplate` 更省事，它的数据是最"干净"的。阶段 2 做缓存时我们会两种都用。

## 12. 第 10 步：Shop 实体类

**文件**：`com/zhilan/zhilanserver/entity/Shop.java`

### 什么是实体类

**和数据库表一一对应的 Java 类**。表里有 `name` 字段，类里就有 `name` 属性；表有 18 列，类就有 18 个字段。

```java
package com.zhilan.zhilanserver.entity;

import com.baomidou.mybatisplus.annotation.FieldFill;
import com.baomidou.mybatisplus.annotation.IdType;
import com.baomidou.mybatisplus.annotation.TableField;
import com.baomidou.mybatisplus.annotation.TableId;
import com.baomidou.mybatisplus.annotation.TableLogic;
import com.baomidou.mybatisplus.annotation.TableName;
import jakarta.validation.constraints.NotBlank;
import lombok.Data;

import java.io.Serializable;
import java.math.BigDecimal;
import java.time.LocalDateTime;

/**
 * 商家实体
 */
@Data
@TableName("shop")
public class Shop implements Serializable {

    @TableId(type = IdType.AUTO)
    private Long id;

    @NotBlank(message = "商家名称不能为空")
    private String name;

    /** 类型：美食/休闲娱乐/酒店民宿/丽人/运动健身/生活服务 */
    @NotBlank(message = "商家类型不能为空")
    private String type;

    private String city;

    private String address;

    private String phone;

    private String businessHours;

    /** 人均价格 */
    private BigDecimal avgPrice;

    /** 评分 0-5 */
    private BigDecimal score;

    /** 销量 */
    private Integer sales;

    /** 评论数 */
    private Integer comments;

    /** 图片URL，逗号分隔 */
    private String images;

    private String description;

    /** 状态 1营业 0停业 */
    private Integer status;

    @TableLogic
    private Integer deleted;

    @TableField(fill = FieldFill.INSERT)
    private LocalDateTime createTime;

    @TableField(fill = FieldFill.INSERT_UPDATE)
    private LocalDateTime updateTime;
}
```

### 逐行讲解（注解是重点）

**`@TableName("shop")`**：告诉 MyBatis-Plus 这个类对应 `shop` 表。
如果不写，默认会用**类名小写**去匹配，也就是 `shop`——正好也能对上。但如果表叫 `t_shop`，就必须写 `@TableName("t_shop")`。**建议养成写上的习惯**，避免依赖默认规则。

**`@TableId(type = IdType.AUTO)`**：`id` 是主键，`AUTO` 表示**数据库自增**。
新增时你不用管 `id`，MySQL 自己分配，MyBatis-Plus 还会把生成的主键回填到对象里（所以 `shopService.save(shop)` 之后 `shop.getId()` 能拿到值）。

**`@NotBlank(message = "...")`**：参数校验注解，**不是** MyBatis 的。
- `@NotBlank`：不能为 null，且去掉空格后长度必须 > 0（专门给字符串用）
- `@NotNull`：不能为 null（给数字、对象用）
- `@NotEmpty`：不能为 null 且不能为空集合

`message` 是校验失败时的提示语——就是全局异常处理器里 `getDefaultMessage()` 取到的那个。

**⚠️ 注意 `jakarta` 而不是 `javax`**：
Spring Boot 3 用的是 `jakarta.validation.constraints.NotBlank`。
如果你从老教程复制成 `javax.validation.constraints.NotBlank`，**编译直接报错**。这是复刻老项目最常见的坑。

**字段类型的选择**：

| 数据库类型 | Java 类型 | 为什么 |
|---|---|---|
| `BIGINT` | `Long` | id 建议用 Long，int 可能不够用 |
| `DECIMAL` | `BigDecimal` | 金额/评分，精度不能丢 |
| `INT` | `Integer` | 用包装类不用 `int`，因为**数据库里可能是 NULL**，`int` 装不下 null |
| `VARCHAR` / `TEXT` | `String` | |
| `DATETIME` | `LocalDateTime` | 新 API，比老的 `java.util.Date` 好用 |

**`@TableLogic`**：标记这个字段是逻辑删除。
配合 `application.yaml` 里的全局配置，MyBatis-Plus 会：
- `removeById(id)` → 实际执行 `UPDATE shop SET deleted=1 WHERE id=?`
- 所有查询自动追加 `WHERE deleted=0`

**`@TableField(fill = FieldFill.INSERT)`**：告诉 MyBatis-Plus "新增时请帮我填充这个字段"。
**它必须和第 8 步的 `MyMetaObjectHandler` 配合**：
- `@TableField(fill=...)` 说"我要填"
- `MyMetaObjectHandler` 说"填什么值"
- 缺一个，自动填充就不生效。

**`FieldFill.INSERT` vs `FieldFill.INSERT_UPDATE`**：
- `createTime` 只在新增时填 → `INSERT`
- `updateTime` 新增和更新都要填 → `INSERT_UPDATE`

**`businessHours` 对应 `business_hours`**：靠 `map-underscore-to-camel-case: true` 自动映射。

## 13. 第 11 步：ShopMapper

**文件**：`com/zhilan/zhilanserver/mapper/ShopMapper.java`

### 你只需要写一行

```java
package com.zhilan.zhilanserver.mapper;

import com.baomidou.mybatisplus.core.mapper.BaseMapper;
import com.zhilan.zhilanserver.entity.Shop;
import org.apache.ibatis.annotations.Mapper;

@Mapper
public interface ShopMapper extends BaseMapper<Shop> {
}
```

### 逐行讲解

**`@Mapper`**：告诉 MyBatis "扫描到这个接口时，**帮我在运行时生成一个实现类**"。
接口没有方法体，怎么用？——MyBatis 用动态代理在运行时生成实现。你直接 `@Autowired` 注入就能用。

**`extends BaseMapper<Shop>`**：**这一步是关键**。
`BaseMapper<T>` 是 MyBatis-Plus 提供的"万能接口"，继承它之后，**你白得了一堆方法**，一个 SQL 都不用写：

| 方法 | 对应 SQL |
|---|---|
| `insert(shop)` | `INSERT INTO shop ...` |
| `deleteById(1L)` | `DELETE FROM shop WHERE id=1` |
| `updateById(shop)` | `UPDATE shop SET ... WHERE id=?` |
| `selectById(1L)` | `SELECT * FROM shop WHERE id=1` |
| `selectList(wrapper)` | `SELECT * FROM shop WHERE <条件>` |
| `selectPage(page, wrapper)` | 分页查询 |
| `selectCount(wrapper)` | `SELECT COUNT(*) FROM shop WHERE <条件>` |

**泛型 `<Shop>` 的作用**：告诉它操作哪张表。它靠 `Shop` 类上的 `@TableName("shop")` 知道表名，靠字段名知道列名。

**如果是复杂 SQL 怎么办？**
自定义方法 + `@Select` 注解，或者写在 XML 里：

```java
// 方式1：注解
@Select("SELECT * FROM shop WHERE city = #{city}")
List<Shop> selectByCity(String city);

// 方式2：XML（复杂 SQL 推荐，配在 resources/mapper/ShopMapper.xml）
List<Shop> selectByCondition(ShopQueryDTO query);
```

阶段 1 用不到，知道有这么回事就行。

## 14. 第 12 步：ShopQueryDTO 查询条件

**文件**：`com/zhilan/zhilanserver/dto/ShopQueryDTO.java`

### 为什么要单独搞个 DTO，不直接用 Shop

因为**查询条件和实体字段根本不是一回事**：

- 用户想按 `keyword`（关键字）查，但表里**没有** `keyword` 这列，它是"name 或 address 模糊匹配"的意思
- 用户还要传 `page`、`pageSize`、`sortBy`——这些是**分页参数，不是表字段**

如果直接用 `Shop` 接参数，这些多出来的东西就没地方放。所以专门定义"接收查询参数"的类，叫 `DTO`（Data Transfer Object，数据传输对象）。

```java
package com.zhilan.zhilanserver.dto;

import lombok.Data;

/**
 * 商家分页查询条件
 */
@Data
public class ShopQueryDTO {

    /** 关键字：匹配名称/地址 */
    private String keyword;

    /** 类型 */
    private String type;

    /** 城市 */
    private String city;

    /** 状态 1营业 0停业，为空查全部 */
    private Integer status;

    /** 排序字段：score / sales / avgPrice */
    private String sortBy;

    /** 是否升序，默认降序 */
    private Boolean asc = false;

    private Integer page = 1;

    private Integer pageSize = 10;
}
```

### 知识点

**默认值**：`private Integer page = 1;`
如果请求里没传 `page`，Spring 会**保留这个默认值**（不会覆盖成 null）。这样就有个兜底。
但注意一点：**如果前端传了 `page=`（空字符串），Spring 可能给你 null**，所以 Service 里还要再兜一层（第 14 步会看到）。

**命名习惯**：
- `XxxDTO`：接收前端传来的参数
- `XxxVO`：返回给前端的对象（可以裁剪字段，比如隐藏手机号）
- `Xxx`（Entity）：和数据库表对应

阶段 1 我们简化了，直接返回 Entity。**真实项目里更规范的做法是加个 `ShopVO`**，把 `deleted` 这类内部字段去掉。这个习惯你以后可以慢慢养成。

## 15. 第 13 步：ShopService 接口

**文件**：`com/zhilan/zhilanserver/service/ShopService.java`

### 为什么要"接口 + 实现类"分开

初学时会觉得多此一举，其实有两个实在的好处：

1. **解耦**：Controller 只依赖接口。哪天要换成 Redis 版本实现，Controller 不用改一个字。
2. **Spring AOP 的基础**：后面阶段 4 的事务、阶段 5 的限流切面，都是**基于接口代理**实现的。一开始就用接口，后面加功能才顺。

```java
package com.zhilan.zhilanserver.service;

import com.baomidou.mybatisplus.extension.plugins.pagination.Page;
import com.baomidou.mybatisplus.extension.service.IService;
import com.zhilan.zhilanserver.dto.ShopQueryDTO;
import com.zhilan.zhilanserver.entity.Shop;

public interface ShopService extends IService<Shop> {

    /**
     * 商家分页查询（关键词/类型/城市/排序）
     */
    Page<Shop> pageQuery(ShopQueryDTO query);

    /**
     * 查询商家详情（阶段2 会在此叠加多级缓存）
     */
    Shop getDetail(Long id);
}
```

### 逐行讲解

**`extends IService<Shop>`**：和 `BaseMapper` 一样，MyBatis-Plus 提供的**万能 Service 接口**。继承后白得这些方法：

| 方法 | 说明 |
|---|---|
| `save(shop)` | 新增 |
| `saveBatch(list)` | 批量新增 |
| `updateById(shop)` | 按 id 更新 |
| `removeById(id)` | 按 id 删除（逻辑删除） |
| `getById(id)` | 按 id 查 |
| `list()` | 查全部 |
| `page(page, wrapper)` | 分页查询 |
| `count()` | 统计 |

**`Page<Shop>`**：MyBatis-Plus 的分页结果对象，里面有：
- `records`：当前页的数据列表
- `total`：总记录数
- `current`：当前页
- `size`：每页条数
- `pages`：总页数

**接口里只声明"要做什么"，不写"怎么做"**——方法和注释就够了。

## 16. 第 14 步：ShopServiceImpl 实现（核心）

**文件**：`com/zhilan/zhilanserver/service/impl/ShopServiceImpl.java`

这是整阶段**最需要理解**的一个类。

```java
package com.zhilan.zhilanserver.service.impl;

import com.baomidou.mybatisplus.core.conditions.query.LambdaQueryWrapper;
import com.baomidou.mybatisplus.extension.plugins.pagination.Page;
import com.baomidou.mybatisplus.extension.service.impl.ServiceImpl;
import com.zhilan.zhilanserver.common.BusinessException;
import com.zhilan.zhilanserver.dto.ShopQueryDTO;
import com.zhilan.zhilanserver.entity.Shop;
import com.zhilan.zhilanserver.mapper.ShopMapper;
import com.zhilan.zhilanserver.service.ShopService;
import org.apache.commons.lang3.StringUtils;
import org.springframework.stereotype.Service;

import java.util.Set;

@Service
public class ShopServiceImpl extends ServiceImpl<ShopMapper, Shop> implements ShopService {

    private static final Set<String> SORT_FIELDS = Set.of("score", "sales", "avgPrice");

    @Override
    public Page<Shop> pageQuery(ShopQueryDTO query) {
        // 兜底：分页参数非法时给默认值
        int page = query.getPage() == null || query.getPage() < 1 ? 1 : query.getPage();
        int pageSize = query.getPageSize() == null || query.getPageSize() < 1 ? 10
                : Math.min(query.getPageSize(), 100);

        LambdaQueryWrapper<Shop> wrapper = new LambdaQueryWrapper<>();
        wrapper.eq(StringUtils.isNotBlank(query.getType()), Shop::getType, query.getType())
                .eq(StringUtils.isNotBlank(query.getCity()), Shop::getCity, query.getCity())
                .eq(query.getStatus() != null, Shop::getStatus, query.getStatus())
                .and(StringUtils.isNotBlank(query.getKeyword()), w -> w
                        .like(Shop::getName, query.getKeyword())
                        .or()
                        .like(Shop::getAddress, query.getKeyword()));

        // 排序：只允许白名单字段，防 SQL 注入
        String sortBy = query.getSortBy();
        boolean asc = Boolean.TRUE.equals(query.getAsc());
        if (StringUtils.isNotBlank(sortBy) && SORT_FIELDS.contains(sortBy)) {
            switch (sortBy) {
                case "score" -> wrapper.orderBy(true, asc, Shop::getScore);
                case "sales" -> wrapper.orderBy(true, asc, Shop::getSales);
                case "avgPrice" -> wrapper.orderBy(true, asc, Shop::getAvgPrice);
                default -> wrapper.orderByDesc(Shop::getId);
            }
        } else {
            wrapper.orderByDesc(Shop::getId);
        }
        return page(new Page<>(page, pageSize), wrapper);
    }

    @Override
    public Shop getDetail(Long id) {
        if (id == null || id <= 0) {
            throw new BusinessException(400, "商家ID不合法");
        }
        Shop shop = getById(id);
        if (shop == null) {
            throw new BusinessException(404, "商家不存在或已下架");
        }
        return shop;
    }
}
```

### 逐行讲解

#### ① 类声明

```java
@Service
public class ShopServiceImpl extends ServiceImpl<ShopMapper, Shop> implements ShopService {
```

- **`@Service`**：标记这是 Service 层的 Bean，Spring 启动时创建它并放进容器，这样 Controller 才能 `@Autowired` 注入。
- **`extends ServiceImpl<ShopMapper, Shop>`**：**注意两个泛型**——第一个是 Mapper 类型，第二个是实体类型。
  继承它之后，我们的 `page()`、`getById()` 这些方法才有实现（都来自 `IService`）。
  `ServiceImpl` 内部已经帮你注入了 `ShopMapper`，用 `baseMapper` 就能访问。
- **`implements ShopService`**：实现我们自己的接口。

**为什么两个都要？** `ServiceImpl` 提供实现，`ShopService` 定义契约。这样 Controller 依赖 `ShopService` 接口，拿到的却是 `ShopServiceImpl` 的实例。

#### ② 排序字段白名单

```java
private static final Set<String> SORT_FIELDS = Set.of("score", "sales", "avgPrice");
```

**这是安全设计，不是多余的。**

想象没有白名单：前端传 `sortBy=id; DROP TABLE shop--`，如果你直接用字符串拼 SQL，数据库就没了。

虽然 `LambdaQueryWrapper` 用的是方法引用（`Shop::getScore`）而不是字符串拼接，安全性本来就高，**但白名单仍然必要**——因为它还要解决另一个问题：

> 用户传了 `sortBy=name`，但 name 不在白名单里 → 走 else 分支按 id 排。**这让排序变成可控的枚举，而不是任意字段。**

`Set.of(...)` 是 Java 9+ 创建不可变集合的写法，`static final` 表示"类级别共享、不可改"。

#### ③ 参数兜底

```java
int page = query.getPage() == null || query.getPage() < 1 ? 1 : query.getPage();
```

三元表达式：`条件 ? 值1 : 值2`——条件成立取值1，否则取值2。

**为什么要兜底？** 前端可能传 `page=0`、`page=-1`，或者压根不传。不兜底的话：
- `LIMIT -1, 10` → SQL 语法错误
- `LIMIT 0, 10` → 用户以为查的是第一页，实际逻辑混乱

```java
int pageSize = query.getPageSize() == null || query.getPageSize() < 1 ? 10
        : Math.min(query.getPageSize(), 100);
```

**`Math.min(..., 100)` 是关键**：限制每页最多 100 条。

**为什么必须限制？** 前端传 `pageSize=1000000`，你一口气从数据库捞一百万条数据，**服务器内存直接爆掉**——这叫"**接口被恶意刷爆**"。真实项目里所有分页接口都必须有这个上限。

#### ④ 条件构造器（重点）

```java
LambdaQueryWrapper<Shop> wrapper = new LambdaQueryWrapper<>();
wrapper.eq(StringUtils.isNotBlank(query.getType()), Shop::getType, query.getType())
```

**`LambdaQueryWrapper` 是什么？**
它是 MyBatis-Plus 用来**动态拼 WHERE 条件**的工具。上面的代码最终会生成：

```sql
SELECT * FROM shop WHERE deleted=0 AND type = '美食' AND city = '杭州'
```

**`eq(条件, 字段, 值)` 的"三参数重载"是精髓**：

第一个参数是**布尔值**。只有为 `true` 时这个条件才会被拼进 SQL。

所以 `StringUtils.isNotBlank(query.getType())` 的意思是：
- 前端传了 `type=美食` → 拼 `AND type='美食'`
- 前端没传 `type` → **这个条件直接消失**，不拼

**这就是为什么不需要写一堆 `if-else`**。对比一下没有这个特性时要怎么写：

```java
// 丑，且容易写错
if (StringUtils.isNotBlank(query.getType())) {
    wrapper.eq(Shop::getType, query.getType());
}
if (StringUtils.isNotBlank(query.getCity())) {
    wrapper.eq(Shop::getCity, query.getCity());
}
// ... 还有 5 个字段
```

**`Shop::getType` 是什么？**
这是**方法引用**（Lambda 的简化写法），等价于 `lambda` 表达式 `shop -> shop.getType()`。

**为什么用方法引用而不是字符串 `"type"`？**
因为**类型安全 + 重构友好**：
- 写字符串 `"type"`：哪天你把字段改名成 `category`，编译器**不会报错**，运行时才炸
- 写 `Shop::getType`：改名后 IDE 一键重构，**编译期就能发现错误**

**链式调用**：`eq()` 返回 wrapper 自身，所以可以 `.eq().eq().eq()` 一路点下去。

**`status` 那个为什么用 `!= null` 判断？**
因为 `status` 是 `Integer`，值可能是 `0`（停业）。
如果用 `StringUtils.isNotBlank` 判断数字类型会出错，而且 **`0` 是有意义的查询条件**（查停业的商家）。所以只判断是否为 null。

> ⚠️ **这里有个新手大坑**：如果用 `status != 0` 判断，那"查停业商家"（status=0）就永远查不到了。

#### ⑤ 括号分组（重点）

```java
.and(StringUtils.isNotBlank(query.getKeyword()), w -> w
        .like(Shop::getName, query.getKeyword())
        .or()
        .like(Shop::getAddress, query.getKeyword()));
```

这段是**整个方法最容易出错的地方**，一定要理解。

**先说 `like`**：`.like(Shop::getName, "火锅")` → SQL 里的 `name LIKE '%火锅%'`。

**再说 `or`**：`.or()` 表示下一个条件用 OR 连接。

**为什么要用 `.and(w -> ...)` 包起来？**

假设不用括号，直接这么写：

```java
wrapper.eq(Shop::getType, "美食")
       .like(Shop::getName, kw)
       .or()
       .like(Shop::getAddress, kw);
```

生成的 SQL 是：

```sql
WHERE deleted=0 AND type='美食' AND name LIKE '%火锅%' OR address LIKE '%火锅%'
```

**问题来了**：`AND` 的优先级比 `OR` 高，所以实际执行顺序是：

```sql
WHERE (deleted=0 AND type='美食' AND name LIKE '%火锅%') OR (address LIKE '%火锅%')
```

**结果完全错了**：它会把**所有城市、所有类型**里地址含"火锅"的商家都查出来，`type='美食'` 这个条件被 OR 掉了！

用 `.and(w -> ...)` 加括号后：

```sql
WHERE deleted=0 AND type='美食' AND (name LIKE '%火锅%' OR address LIKE '%火锅%')
```

**这才是我们要的：先限定"美食"类型，再在其中匹配名字或地址。**

`w -> ...` 里的 `w` 是一个新的 wrapper，代表"括号里面"的内容。这是 Lambda 表达式的参数。

> **记住这个结论**：**只要一组条件里出现 `or`，就必须用 `.and(w -> ...)` 或 `.or(w -> ...)` 把它们括起来。**这是 SQL 条件拼装的头号 bug 来源。

#### ⑥ 排序

```java
if (StringUtils.isNotBlank(sortBy) && SORT_FIELDS.contains(sortBy)) {
    switch (sortBy) {
        case "score" -> wrapper.orderBy(true, asc, Shop::getScore);
        case "sales" -> wrapper.orderBy(true, asc, Shop::getSales);
        case "avgPrice" -> wrapper.orderBy(true, asc, Shop::getAvgPrice);
        default -> wrapper.orderByDesc(Shop::getId);
    }
} else {
    wrapper.orderByDesc(Shop::getId);
}
```

**`orderBy(条件, 是否升序, 字段)`**：第二个参数 `true` = 升序（ASC），`false` = 降序（DESC）。

**注意第一个参数是 `true`（恒真）**——因为这里是用 `switch` 分支判断的，不需要再传条件了。

**`switch` 的箭头语法**（Java 14+）：
```java
case "score" -> wrapper.orderBy(...);
```
比老写法简洁，而且**不会像老 `switch` 那样"贯穿"**（老写法忘了 `break` 会继续执行下一个 case，是个经典 bug）。

**`default`**：所有 case 都不匹配时执行。这里兜底按 id 降序（相当于"最新的排前面"）。

**`Boolean.TRUE.equals(query.getAsc())` 的写法为什么这么啰嗦？**
因为 `query.getAsc()` 是 `Boolean` 包装类型，**可能是 null**。
如果写 `query.getAsc()` 直接拆箱，遇到 null 会抛 `NullPointerException`。
`Boolean.TRUE.equals(x)` 这种"常量.equals(变量)"的写法，null 也安全（返回 false）。**这是 Java 里推荐的安全比较习惯。**

#### ⑦ 执行分页

```java
return page(new Page<>(page, pageSize), wrapper);
```

**`new Page<>(page, pageSize)`**：构造分页参数，即"第 page 页，每页 pageSize 条"。
注意**页码从 1 开始**，不是 0（这点和很多语言不同）。

**`page(...)` 方法**：来自 `ServiceImpl`（即上面继承的那个）。
它内部会：
1. 被第 7 步注册的 `PaginationInnerInterceptor` 拦截
2. 自动执行 `SELECT COUNT(*)` 得到总数
3. 自动改写 SQL 加上 `LIMIT` 取当前页数据
4. 组装成 `Page<Shop>` 对象返回

**注意它是 `this.page(...)` 的简写**——因为我们继承了 `ServiceImpl`，可以直接调用。

#### ⑧ getDetail 方法

```java
public Shop getDetail(Long id) {
    if (id == null || id <= 0) {
        throw new BusinessException(400, "商家ID不合法");
    }
    Shop shop = getById(id);
    if (shop == null) {
        throw new BusinessException(404, "商家不存在或已下架");
    }
    return shop;
}
```

**两层校验，各有各的意义**：

1. **`id == null || id <= 0`** → **参数合法性校验**。
   这是"请求本身有问题"，返回 **400**。
   顺手说一句：`id <= 0` 这个判断还能避免有人用负数 id 去试探。

2. **`shop == null`** → **业务状态校验**。
   请求合法，但数据不存在，返回 **404**。

**为什么要区分 400 和 404？** 因为前端处理方式不同：
- 400 → 提示"参数错误"，通常是前端 bug
- 404 → 提示"商家不存在"，可能是用户手输的 url 失效了

**`getById(id)`** 来自 `IService`，实际执行：
```sql
SELECT * FROM shop WHERE id=? AND deleted=0
```
（`deleted=0` 是逻辑删除自动加的）

**注意这里 `throw` 之后没有 `return`**——因为异常会中断执行，编译器知道 `throw` 之后不会继续往下走，所以不需要。

**这个方法在阶段 2 会被改造**：加上 Caffeine + Redis 缓存。到时候你会看到"**不改 Controller，只改 Service**"的好处。

**文件**：`com/zhilan/zhilanserver/controller/ShopController.java`

```java

/**
 * 商家信息接口

@RestController
```

> **但真实项目建议逐个 import**（IDEA 里按 `Ctrl+Alt+O` 可以优化 import），避免通配符带来的类名冲突。教程里为了行数短用了 `*`。

### 逐行讲解

#### ① 类上的注解

**`@RestController`** = `@Controller` + `@ResponseBody`。
- `@Controller`：标记这是处理 HTTP 请求的类
- `@ResponseBody`：方法返回值**直接转成 JSON** 写进响应体

不写 `@ResponseBody` 的话，Spring 会把你返回的字符串当成"**页面名字**"去找 HTML 模板，结果就是 404。

**`@RequestMapping("/shop")`**：**类级别的路径前缀**。
配合方法上的 `@GetMapping("/page")`，最终路径是 `/shop/page`。

**`@RequiredArgsConstructor`**：Lombok 注解，为**所有 `final` 字段**生成一个构造方法：

```java
public ShopController(ShopService shopService) {
    this.shopService = shopService;
}
```

**为什么要用构造方法注入，而不是 `@Autowired` 字段注入？**

| 方式 | 问题 |
|---|---|
| `@Autowired` 字段注入 | ❌ 字段可以是 null（偷偷失败）❌ 无法用 `final` ❌ 单元测试不方便 |
| **构造方法注入**（推荐） | ✅ 用 `final` 保证一定被赋值 ✅ 启动时就报错，不会运行时才发现 ✅ 测试时可以直接 new |

**如果只有一个构造方法，Spring 4.3+ 会自动用它注入，不需要写 `@Autowired`。** 这就是 `@RequiredArgsConstructor` + `final` 这么流行的原因。

**`@Validated`**：开启**方法级参数校验**（配合方法参数上的 `@NotBlank` 等注解使用）。
注意它和 `@Valid` 不一样，`@Valid` 是校验**对象内部**的字段（比如 `Shop` 里的 `@NotBlank`）。

#### ② 分页接口

```java
@GetMapping("/page")
public Result<Page<Shop>> page(ShopQueryDTO query) {
    return Result.ok(shopService.pageQuery(query));
}
```

**`@GetMapping("/page")`**：只接受 **GET** 请求，路径 `/shop/page`。

**参数 `ShopQueryDTO query` 没有注解**：Spring 会自动把 **URL 查询参数**（`?type=美食&page=1`）按**字段名**绑定到对象里。
- URL 里的 `?type=美食` → 自动调 `query.setType("美食")`
- 没传的字段保持默认值（`page=1`、`pageSize=10`）

这个机制叫"**参数绑定**"。字段名必须和 URL 参数名一致。

**返回 `Result<Page<Shop>>`**：
- `Result` 里包着 `Page<Shop>`
- `Page` 里包着 `List<Shop>` 和分页信息
- 最终 JSON 长这样：

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "records": [ { "id": 5, "name": "美发沙龙", ... } ],
    "total": 5,
    "size": 10,
    "current": 1,
    "pages": 1
  }
}
```

**`Result.ok(...)`**：静态工厂方法，包装成成功响应。

#### ③ 详情接口

```java
@GetMapping("/{id}")
public Result<Shop> detail(@PathVariable Long id) {
    return Result.ok(shopService.getDetail(id));
}
```

**`/{id}`**：路径变量（占位符）。访问 `/shop/3` 时，`{id}` 就匹配到 `3`。

**`@PathVariable`**：把路径里的 `3` 绑定到方法参数 `id` 上。
**名字必须一致**：路径里叫 `{id}`，参数就叫 `id`。不一致的话要写 `@PathVariable("id")`。

**路径顺序提醒**：`/shop/page` 和 `/shop/{id}` 会冲突吗？
不会。Spring 优先匹配**精确路径** `/shop/page`，再匹配带变量的 `/{id}`。所以访问 `/shop/page` 不会跑到 detail 里去。

> ⚠️ 但如果你写 `/shop/getById/{id}` 这种就没问题；如果写 `/{id}` 和 `/{name}` 两个同级的变量路径，就会启动报错（歧义）。

#### ④ 新增接口

```java
@PostMapping
public Result<Long> save(@Valid @RequestBody Shop shop) {
    shop.setId(null);
    ...
    shopService.save(shop);
    return Result.ok(shop.getId());
}
```

**`@PostMapping`**：只接受 **POST**，路径就是 `/shop`（类上已经定义了前缀）。

**`@RequestBody`**：把**请求体里的 JSON** 反序列化成 `Shop` 对象。
- `@RequestBody` ← 读请求体（POST/PUT 的 JSON）
- 不加 `@RequestBody` ← 读 URL 参数

对着 Postman 看更清楚：

```
POST /shop
Body (raw, JSON):
{
  "name": "测试商家",
  "type": "美食",
  "city": "杭州"
}
```

**`@Valid`**：触发 `Shop` 类里那些 `@NotBlank` 校验。
- 校验失败 → 抛 `MethodArgumentNotValidException`
- → 被第 6 步的 `GlobalExceptionHandler` 捕获
- → 返回 `{code:400, msg:"name: 商家名称不能为空"}`

**`shop.setId(null)` 为什么必须写？**
防止有人恶意传 `{"id": 999}`，如果直接用，`save()` 可能会变成"指定 id 插入"，甚至覆盖已有数据。**主动置空，让数据库自增分配**，这是安全习惯。

**`shop.setSales(... == null ? 0 : ...)` 为什么要手动兜底？**
数据库里 `sales` 有 `DEFAULT 0`，但 MyBatis-Plus 的 `insert` 会把所有非 null 字段都写进 SQL。
如果 `sales` 是 null，插入的 SQL 里就是 `sales = NULL`（**显式传 NULL 会覆盖掉数据库默认值！**），而不是用 `DEFAULT 0`，结果字段就是 NULL。
所以要在代码里兜底。

> **记住这个点**：**数据库的 `DEFAULT` 只在"SQL 里完全没提这个字段"时生效。** 如果显式传了 `NULL`，就存 NULL。

**`return Result.ok(shop.getId())`**：`save()` 之后 MyBatis-Plus 会把自增主键**回填**到 `shop` 对象里，所以这里能拿到新 id 返回给前端。

#### ⑤ 更新接口

```java
@PutMapping
public Result<Void> update(@RequestBody Shop shop) {
    if (shop.getId() == null) {
        return Result.fail(400, "id 不能为空");
    }
    shopService.updateById(shop);
    return Result.ok();
}
```

**`@PutMapping`**：按 RESTful 规范，**更新**用 PUT。

**`updateById` 的"选择性更新"特性**（很重要）：
MyBatis-Plus 的 `updateById` **只更新非 null 字段**。
所以你传 `{"id":1, "name":"新名字"}`，它生成的 SQL 是：

```sql
UPDATE shop SET name='新名字', update_time=... WHERE id=1
```

其他字段不动。这正是我们想要的。

> ⚠️ **反过来说**：你**没法用它把某个字段改成 NULL**（因为 null 会被忽略）。真要置空得用 `UpdateWrapper` 显式指定。这个坑记住。

**返回 `Result<Void>`**：更新操作没有数据要返回，所以数据部分是 `Void`，前端只看 `code`。

#### ⑥ 删除接口

```java
@DeleteMapping("/{id}")
public Result<Void> delete(@PathVariable Long id) {
    shopService.removeById(id);
    return Result.ok();
}
```

**`@DeleteMapping`**：DELETE 请求。

**`removeById(id)` 实际执行的是 UPDATE 而不是 DELETE**——因为第 10 步的 `@TableLogic` + 配置里的逻辑删除。

```sql
UPDATE shop SET deleted=1 WHERE id=? AND deleted=0
```

**这就是"逻辑删除"的意义**：数据还在库里，只是标记为已删除，查询时自动过滤掉。可追溯、可恢复。

### 19.2 常见报错对照表

| 报错信息 | 原因 | 解决 |
|---|---|---|
| `The server time zone value ... is unrecognized` | URL 少了 `serverTimezone` | URL 加 `&serverTimezone=Asia/Shanghai` |
| `Public Key Retrieval is not allowed` | MySQL 8 加密方式 | URL 加 `&allowPublicKeyRetrieval=true` |
| `Access denied for user 'root'@'localhost'` | 密码错 | 检查 `application.yaml` 的 `password` |
| `Unknown database 'zhilan'` | 库没建 | 执行 `sql/init.sql` |
| `Table 'zhilan.shop' doesn't exist` | 表没建 | 同上 |
| `Unable to connect to Redis` / `Connection refused` | Redis 没启动 | 启动 Redis 服务 |
| `cannot find symbol: method getName()` | Lombok 没生效 | 装 Lombok 插件 + 开启 Annotation Processing |
| `package javax.validation.constraints does not exist` | 用了老包的注解 | 改成 `jakarta.validation.constraints.*` |
| `404` 且返回的是一串 HTML | 漏了 `@ResponseBody` / `@RestController` | 检查 Controller 注解 |
| `total` 永远是 0，但 `records` 有数据 | 分页插件没注册 | 检查 `MybatisPlusConfig` |
| `createTime` 是 null | 自动填充没配好 | 检查 `@TableField(fill=...)` + `MyMetaObjectHandler` |
| 查询结果比预期多很多 | `.and(w -> ...)` 漏了 | 检查组合条件的括号 |
| 端口 8080 被占 | 有别的程序在用 | `netstat -ano \| findstr 8080` 找到 PID 后 `taskkill /PID xxx /F`，或改 `server.port` |

### 19.3 调试技巧（三件套）

排查问题的三板斧：**看日志 → 打断点 → 写测试**。下面逐个详细讲。

#### 技巧 1：看 SQL 日志（最常用）

**先确认已开启**：`application.yaml` 里有这一行

```yaml
mybatis-plus:
  configuration:
    log-impl: org.apache.ibatis.logging.slf4j.Slf4jImpl
```

它的意思是"让 MyBatis 每次执行 SQL 时把 SQL 打印到日志"。**没配就没有日志。**

**在哪看**：IDEA 底部 `Run` 面板（打印 `Started ZhilanServerApplication` 的那个窗口）。调接口时日志会实时滚出来。

**怎么读**——三行一组：

```
==>  Preparing: SELECT COUNT(*) AS total FROM shop WHERE deleted=0 AND (type = ?)
==> Parameters: 美食(String)
<==      Total: 1
==>  Preparing: SELECT id,name,type,... FROM shop WHERE deleted=0 AND (type = ?) ORDER BY id DESC LIMIT ?
==> Parameters: 美食(String), 10(Long)
<==      Total: 2
```

| 标记 | 含义 |
|---|---|
| `==> Preparing:` | 要执行的 SQL，`?` 是占位符 |
| `==> Parameters:` | 每个 `?` 实际填的值和类型 |
| `<== Total:` | 查询返回几行 |
| `<== Updates:` | 增删改影响几行（只在写操作时出现） |

**为什么它最有用**：能让你把"你以为的 SQL"和"框架实际生成的 SQL"对上。比如括号问题一看就知道：

```sql
-- ❌ 括号丢了，type 条件被 OR 吃掉
WHERE deleted=0 AND type = ? AND name LIKE ? OR address LIKE ?

-- ✅ 正确
WHERE deleted=0 AND (type = ? AND (name LIKE ? OR address LIKE ?))
```

> 小技巧：Run 面板按 `Ctrl+F` 搜 `Preparing`，快速定位所有 SQL。

#### 技巧 2：断点调试（最强大）

**适用**：想知道某个变量的值、想确认走进了哪个 `if` 分支、**想看拼出来的查询条件**。

**第一步：下断点**
打开 `ShopServiceImpl.java`，在 `pageQuery` 里你想停的那行，**点行号右边的灰色竖条** → 出现红点。
快捷键：光标停在该行按 `Ctrl + F8`。取消：再点一次红点。

**第二步：用 Debug 模式启动（⚠️ 最容易搞错）**
不是绿色三角 ▶，是它右边的**绿色小虫子 🐞**。快捷键 `Shift + F9`。
⚠️ **必须重新启动**。已经在 Run 模式跑着的应用，断点不生效。

**第三步：发请求，程序会停住**
用 Postman 调 `GET /shop/page?type=美食`。这时会发生两件"吓人"但正常的事：
1. IDEA 自动弹到最前面，停住那行变**蓝色高亮**
2. **Postman 一直转圈不返回** ← 正常，程序被你按了暂停键

**认识调试界面**：

```
Frames（调用栈）          ← 方法调用链，点任意一行可跳过去看
  pageQuery:24
  ShopController.page:27

Variables（变量）⭐       ← 当前所有变量的实时值
  query = {ShopQueryDTO@123}
    type = "美食"         ← 点小三角展开
    page = 1
```

- **Frames**：最上面是当前位置；点下面任意一行能跳到上层方法看变量
- **Variables**：最有用的区域。值是红色的 = null
- **蓝色高亮行 = 即将执行、还没执行**（所以高亮行上的变量还是 null，按 `F8` 之后才有值）

**五个核心快捷键（记这 5 个就够）**：

| 快捷键 | 名称 | 作用 |
|---|---|---|
| **`F8`** | Step Over | 执行当前行，跳到下一行（⭐ 最常用） |
| **`F7`** | Step Into | 钻进被调用的方法内部 |
| **`Shift + F8`** | Step Out | 从当前方法跳出去 |
| **`F9`** | Resume | 放行，继续跑到下一个断点或结束 |
| **`Alt + F8`** | Evaluate Expression | ⭐⭐ 求值任意表达式 |

> **建议**：现在就连按 `F8`，看着蓝色高亮一行行往下走，同时盯着 `Variables` 面板里 `page`、`pageSize`、`wrapper` 的变化。

**⭐ 重头戏：看拼出来的 SQL（最值钱的一招）**

1. 断点下在 `wrapper` 那几行**之后**（第 36 行附近）
2. **Debug 模式**启动，调 `GET /shop/page?type=美食&keyword=杭州`
3. 程序停住后按 **`Alt + F8`**，在弹出的框里输入：
   ```java
   wrapper.getSqlSegment()
   ```
4. 点 `Evaluate`，会看到：
   ```
   (deleted = 0 AND type = #{ew.paramNameValuePairs.MPGENVAL1} AND (name LIKE #{...MPGENVAL2} OR address LIKE #{...MPGENVAL3}))
   ```
   **重点看括号在不在** ✅

想看参数的实际值，再 Evaluate 一个：
```java
wrapper.getParamNameValuePairs()
```
能拿到 `MPGENVAL1 = 美食`、`MPGENVAL2 = %杭州%` 这样的对应关系。

**⚠️ 怎么结束调试（新手最容易栽）**

- 方式 A：按 `F9`（Resume）放行，让当前请求正常返回
- 方式 B（推荐）：点 Debug 面板的**红色方块 ⏹ Stop**
- **不点会怎样？** 应用还占着 8080 端口，下次启动报 `Port 8080 was already in use`

**断点管理**：断点不会自动消失，下次还会停。按 `Ctrl + Shift + F8`（或点 Debug 面板左侧"两个红点"图标）可以禁用/删除断点。

**常见困惑速查**：

| 现象 | 原因 |
|---|---|
| 断点不停 | ① 用了 Run 不是 Debug ② 代码没走到那行 ③ 断点被禁用 |
| Postman 一直转圈 | **正常**，程序停在断点等你。按 `F9` 放行 |
| 改了代码没效果 | 要重新 Debug 启动 |
| 高亮那行的变量是 null | 正常，那行还没执行，按 `F8` 后才有值 |
| 启动报端口占用 | 上次 Debug 没停，点红色方块 ⏹ |

#### 技巧 3：写单元测试

**适用**：同样的逻辑要反复验证，不想每次都开 Postman 填参数。

**位置**：`src/test/java/com/zhilan/zhilanserver/`（注意是 `test` 不是 `main`）。

```java
package com.zhilan.zhilanserver;

import com.baomidou.mybatisplus.extension.plugins.pagination.Page;
import com.zhilan.zhilanserver.dto.ShopQueryDTO;
import com.zhilan.zhilanserver.entity.Shop;
import com.zhilan.zhilanserver.service.ShopService;
import org.junit.jupiter.api.Assertions;
import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.context.SpringBootTest;

@SpringBootTest
class ShopServiceTest {

    @Autowired
    private ShopService shopService;

    /** 测试：按类型分页查询 */
    @Test
    void testPageQueryByType() {
        // 1. 准备参数
        ShopQueryDTO query = new ShopQueryDTO();
        query.setType("美食");

        // 2. 调用业务方法
        Page<Shop> page = shopService.pageQuery(query);

        // 3. 打印结果（调试用）
        System.out.println("总条数 = " + page.getTotal());
        page.getRecords().forEach(s ->
                System.out.println(s.getId() + " | " + s.getName()));

        // 4. 断言（验证结果对不对）
        Assertions.assertEquals(2, page.getTotal(), "美食类商家应该是 2 家");
    }

    /** 测试：详情查询 */
    @Test
    void testGetDetail() {
        Shop shop = shopService.getDetail(1L);
        System.out.println(shop);
        Assertions.assertNotNull(shop);
        Assertions.assertEquals("老王火锅", shop.getName());
    }

    /** 测试：查不存在的商家，应该抛异常 */
    @Test
    void testGetDetailNotFound() {
        Assertions.assertThrows(Exception.class, () -> shopService.getDetail(99999L));
    }
}
```

**怎么运行**：保存后，**方法名左边会出现绿色小三角 ▶**，点它 → `Run 'xxx()'`。

- 点方法左边的 ▶ → 只跑这一个测试
- 点类名左边的 ▶ → 跑这个类里所有测试
- ✅ 绿色勾 = 通过；❌ 红色叉 = 失败，点开看异常

**关键注解**：

| 注解 | 作用 |
|---|---|
| `@SpringBootTest` | **启动完整 Spring 容器**，有这个才能 `@Autowired` 注入 Service |
| `@Test` | 标记这是个测试方法（来自 JUnit 5） |
| `@Autowired` | 注入 Bean，测试类里可以随便注入 Service |

**注意事项**：

- ⚠️ `@SpringBootTest` 会**完整启动应用**，所以 MySQL、Redis **必须开着**，否则启动失败
- ⚠️ 测试方法必须是 `void` 且**不能有参数**，否则 JUnit 不认
- ⚠️ **断言比 `println` 强**：`Assertions.assertEquals(期望值, 实际值, "失败提示")`，不符合预期会直接报错，一眼看出问题
